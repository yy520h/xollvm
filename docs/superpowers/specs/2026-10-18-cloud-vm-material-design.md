# 构建绑定的动态 VM 执行材料与分代租约设计

日期：2026-10-18

状态：2026-10-18 用户已确认本书面规格，进入实施计划编写阶段。本文规定目标架构，不代表当前工具链已经实现。

## 1. 设计来源与已确认决策

用户提供《动态VM保护架构_方案总设计_v1.md》，要求云端材料参与具体 VM 的正确执行，消除现有合法偏移恒为零的通用替代点。用户允许按 build_id 将构建秘密材料登记并保存在云端，接受协议认证、秘密生命周期和动态执行方面的修正。

已确认三个可选模式：

| 模式 | 规则 |
| --- | --- |
| 1：启动会话级 A | 每次启动获取新的会话执行材料；本次进程会话内使用，下次启动重新获取 |
| 2：持续租约级 B | 租约 120 秒，第 110 秒开始续期；未取得新材料时，到期后的新调用不能消费旧材料 |
| 3：区域分级 | 普通区域 A，重点区域 B，严重区域 C；C 每次关键操作取得专属材料 |

B 的首版边界采用调用级固定：有效期内进入函数并取得材料的调用允许完成；到期后的下一次调用必须取得有效材料。长调用中途续期需要独立的状态迁移设计，不属于首版保证。

后台只进行网络预取、认证和候选代准备，不循环执行保护函数，不通过 kill 或后台故意触发信号模拟租约失效。真实业务进入保护区域而无可用材料时，由同步故障路径结束执行。

## 2. 当前实现依据及替换对象

- `VMPass_Dispatch.cpp`：中央分发和 threaded tail 调用 `__zone_get_dispatch_offset()`，将结果加到本地已可计算的 handler 索引。
- `../demo/jni/zone_runtime/cloud_value_manager.cpp`：用 V 和窗口编号计算截断 HMAC；合法值对应零偏移。
- 用户提供的 `../capability_v1.js`：用服务端密钥、窗口和候选序号生成 V，搜索零偏移条件；不按具体 VM 编码产生执行材料。
- `VMPass_Crypto.cpp`：当前字节码加密及白盒生成在本地构建完成，其完整运行能力不能直接作为新云模式的无授权回退。
- `../demo/jni/zone_runtime/zone_wrapper.cpp` 与 capability client：已有登录、租约、响应认证和请求绑定逻辑可作为集成依据，但不能将现有协议响应视为新版执行包。

现有 encodedTargets 描述符、白盒实例和静态 handler 也不能仅改名便宣称满足新架构。新云模式必须检查最终产物，而非只检查 IR 中存在调用。

## 3. 目标与边界

### 3.1 必须达到的目标

1. 未获得匹配材料的最终客户端产物不能独立恢复保护区域的完整执行能力。
2. 固定返回 0、1 或任意公开常量不能代替有效执行材料。
3. 执行材料绑定具体构建、区域、会话、代号；操作级材料另外绑定操作实例与输入。
4. 普通续期、并发调用、递归、嵌套 VM 和正常退出不得发生材料混用或生命周期竞争。
5. 缺材料时，在受保护业务产生副作用之前同步失败；不执行未经认证的机器码。
6. 功能测试、协议测试、产物审计与补丁攻击验收分别报告。

### 3.2 不能声称的性质

- 已交付密钥不会因为 expire 到来在数学上自动失效。
- 软件 ECDH、秘密分片、即时擦除和会话随机化不证明客户端无法捕获等价执行能力。
- 本地期限管理不能阻止完全控制进程的攻击者同时冻结时钟、代码和旧代状态。
- 地址变化不代表捕获的 handler 语义或明文字节码失去分析和复用价值。
- C 级仅绑定请求而没有服务端必要状态或计算时，不能声称解决本地完整重放。

威胁模型包含离线分析、伪造服务端、网络重放、动态 hook、固定返回值补丁、材料截获及进程状态冻结。对可控客户端的后几项进行实测，不能把尚未抵抗的攻击标为不可能。

## 4. 组件与职责

| 组件 | 职责 |
| --- | --- |
| 编译器 | 生成区域身份、规范 VM 表示及材料依赖；拒绝无法支持的边界；发射有效配置证明 |
| 构建封装器 | 分离公开产物与秘密登记包；检查没有原生回退和等价完整解码材料；计算内容身份 |
| 云端构建仓库 | 保存构建的区域秘密与规范执行描述；按授权策略产生匹配执行包 |
| 协议服务 | 认证登录和设备凭据，协商会话，绑定请求，执行吊销、续期及操作级状态管理 |
| 客户端材料运行时 | 验证和接收执行包，维护单调期限、候选代、不可变调用句柄及清理 |
| VM 执行后端 | 消费已认证的配套编码与材料，执行计算；后续扩展链式即时解密 handler |
| 验收器 | 检查真实材料依赖、产物和数据流；区分预期故障与无关崩溃 |

服务端持有构建材料，不等于服务端必须执行全部业务。C 级的服务端必要步骤按具体操作另行确定。

## 5. 构建身份与秘密登记

构建封装产生两份不同交付物：

1. 公开客户端：公开引导信息、认证公钥、保护内容的密文或公开引用、ABI/VM 格式版本，以及非秘密运行骨架。
2. 秘密登记包：区域对应的解码材料、规范 VM 表示、编码转换所需描述和授权策略。仅进入受认证的构建登记渠道与云端仓库，不进入客户端发布包、Git 或普通日志。

build_id 根据规范化公开清单的内容摘要确定。清单中的身份字段本身及后续 seal 摘要不参与其自身的递归计算；另行绑定最终公开产物摘要。region_id 在同一构建中唯一；源代码中的区域名不能替代密码学内容绑定。

登记采用先上传待发布版本、验证配对关系、再原子启用的流程。客户端发布前须确认云端已启用准确的内容身份。构建秘密不得复用混淆用的可复现 seed 生成；测试密钥与生产材料隔离。

区域策略由登记清单决定。客户端可请求区域，但不能通过自报 A/B/C 等级降级服务端策略。未登记、吊销、构建摘要不匹配或 VM 格式不支持时拒绝发放，不回退旧零偏移模式。

## 6. 执行材料如何与密文匹配

本设计要求明确的配对关系，不允许任意 session seed 直接解密固定构建密文。

### 6.1 配对执行包

云端利用已登记的规范区域描述，产生一个执行包：

```text
身份：build_id / region_id / session_id / generation
内容：本代编码的执行载荷、编码布局描述、必要的解码材料
期限：授权模式、生效信息、租约上限
绑定：请求摘要、协议版本、执行载荷摘要
```

载荷与解码材料必须成套产生。基础阶段选择服务端从规范字节码生成本代 opcode 映射、重编码后的字节码和对应解码描述，再对载荷进行认证加密。客户端不能只收到随机映射却继续使用不匹配的旧字节码。服务端转换必须保留指令边界、控制流、CALL ABI 和原业务语义；不同会话编码确实不同，同时均与原生结果一致。

如果重用构建密文，协议必须提供从该密文到本代执行表示的实际转换路径，并验证转换关系；不能把每次用不同传输密钥包装同一构建主钥称为会话执行随机化。

优先按区域分配和按需取得，不向客户端发放可解开全部区域的永久构建主钥。区域内片段化交付作为扩大保护的后续能力；首版按区域完整发放时，必须报告一次捕获可覆盖整个区域这一事实。

### 6.2 正确执行依赖

```text
匹配的本代编码载荷 + 匹配的本代解码材料 + 匹配的调用上下文
    → 正确的 VM 操作与控制流
```

公开客户端不得包含可直接执行的完整等价规范业务字节码，不得包含可独立还原保护内容的完整密钥路径，也不得保留保护函数的完整原生回退。普通 VM skeleton 与通用 handler 可以公开存在；若声明 handler 机密保护，则最终产物还必须满足第 11 节的独立要求。

缺少材料时不利用无界索引、错误机器码或任意跳转制造随机故障。材料不可用与认证失败进入明确的同步失败边界，使用进程默认致命 trap 路径；不以返回成功或执行残缺业务代替失败。该 trap 是故障行为，不是不可绕过证明。

## 7. 会话与协议要求

新协议独立版本化，与 capability_v1 零偏移响应不混用。继续承接真实卡密/登录、有效租约和吊销检查；设备字符串本身不是身份凭证。

- 使用经认证的临时密钥协商、标准 KDF 和 AEAD；服务端身份与密钥版本必须绑定。
- 请求与响应绑定完整握手 transcript、双方密钥身份、nonce、请求标识、构建、区域、模式、会话、代号和载荷摘要。
- 接收端验证 AEAD tag、签名或协议认证证明、长度、版本及身份之后才发布材料。
- nonce、generation、counter 是不同概念：nonce 防请求混淆；generation 标记材料版本；服务端 counter 需要事务化存储与并发语义。
- 客户端记忆的最大 counter 可检测正常运行中的旧响应，但不能作为可控客户端不可回滚的证明。
- 单独的签名密钥与密钥协商密钥分工管理；不复用现有签名私钥充当未经设计的 ECDH 密钥。
- 临时会话密钥与子密钥按用途分离；协商、派生与 AEAD 中间状态最短生命周期处理。软件中不承诺共享秘密从未存在。
- 私钥优先由受控密钥服务托管；缺少 HSM 时不得标称已有硬件隔离。静态服务端协商密钥不自动提供前向保密，协议评审须明确此属性。

完整 wire format、算法套件和错误码作为协议子规格，在其实现之前单独审核；本总规格不作为可直接部署的密码协议。

## 8. 120/110 秒租约与时间依据

服务端决定授权期限，本地运行时执行期限管理。Android 使用包含休眠时间的单调时钟管理进程内租约；不得用可修改的系统日期单独延长有效期。

请求发出时记录本地单调时刻 t0，接收时记录 t1。协议响应绑定本次请求并给出有效时长 D，D 不得超过 120 秒。保守的本地期限为 t0 + D；若响应另有更短的可信剩余期限，只能缩短。t1 已超过期限的响应不能发布。预取起点为 t0 + 110 秒；响应延迟导致已过预取起点时立即调度续期，不延长旧期限。

这里的 120/110 秒以当前材料所绑定请求的发送时刻为基准，不是每次使用材料重新计时。若服务端缩短 D，续期起点相应提前至 t0 + max(0, D - 10 秒)，不能等到期限之后才开始预取。

预取采用有界超时、退避和抖动，不允许请求持续占用材料锁；不能用重试完成时间重置旧代租约。响应必须属于当前会话和允许的新代，迟到旧响应不覆盖新状态。

成功续期后，仅在新调用获取句柄的边界原子切换。续期失败不后台 trap/kill；到期旧代不能再被新调用取得。已固定旧代的调用允许完成。

断网恢复后，新的业务调用可以同步尝试取得材料；必须受明确请求超时约束。若取得有效材料则继续，否则在保护业务副作用前同步故障；旧材料不会因重试而重新有效。

A 不因 B 区域续期失败而自动失效。C 不得沿用 A/B 句柄绕过逐次授权。服务端吊销对已交付 A 材料没有即时远程擦除保证；B 体现在下一次有效续期及期限边界，C 体现在下一次操作授权。

## 9. 调用与并发生命周期

每次进入受保护入口，获取不可变的配对代句柄：身份、编码、解码上下文及生命周期引用作为整体固定。获取动作必须在过期判断与引用建立之间有线性化点，避免检查后过期清理导致悬空引用。

- 调用期间不改变该句柄对应的密钥和布局。
- 旧代到期后停止新获取，最后一个活跃引用释放后清理秘密与缓冲区；不在仍有调用时强行擦除。
- 递归再次进入保护入口算新调用；新的 B 调用重新检查期限，不能自动继承已过期外层句柄。
- 编译器内部 nested VM helper 属于当前调用实现时，使用该调用固定上下文；独立业务保护区域按自身策略获取，不隐式降级。
- 并发获取、续期与退出不得在网络请求期间持有执行状态锁。
- 退出先停止并回收预取线程，再协调活跃调用释放；fork 后不得继承父进程的有效会话，子进程必须重新建立授权。
- 首版拒绝穿越保护边界的未支持 EH、longjmp 等非局部退出，不以泄漏或悬空句柄方式维持运行。

无限长调用可能无限保留已取得的旧代能力，这是调用级边界的直接结果。需要限制此能力的业务必须拆分边界；首版不宣称强制调用中途过期。

## 10. C 级关键操作

操作材料绑定 build_id、region_id、session_id、invocation_id、规范输入摘要和服务端操作状态。操作输入必须由集成者提供确定的规范化表示，不能简单哈希任意指针地址。

服务端按操作实例管理授权和重试幂等关系；同一请求重试不能产生多次不可逆业务提交。授权、材料交付与业务提交是不同事件，不把请求发出即视为成功消费。

若服务端控制实际副作用或必需的新计算材料，应以服务端权威记录拒绝新的未授权操作及重复提交。若业务完全在本地且可从一次捕获重建其全部计算，C 只能证明在线请求绑定，不能宣称捕获后无法离线复现。

因此每个 C 区域交付时必须说明服务端究竟保留哪项必要状态、结果或材料，以及没有该项时不能完成的具体操作。没有这种依赖的区域不能报告“服务端强防重放已达标”。

## 11. 链式直跳、即时解密和 chaff 的阶段边界

基础材料架构先建立；原 v1 的执行加固作为后续独立交付阶段，不在基础阶段被删除，也不能提前标记完成。

- 链式直跳复用 threaded execution 思路，但须审计公共解码、代码发布与缓冲区入口，不能声称无中央 dispatch 就没有公共观察点。
- native handler 加密必须在最终机器码与重定位确定后封装，处理 PC-relative 引用、外部调用、PIE、指令缓存和可执行权限。仅在 IR 中加密一段数据不算已实现。
- 动态缓冲区遵循写入与执行分离、认证后发布、离开执行区后擦除；并发与嵌套调用不得复用仍在执行的缓冲区。不能写 RX 页或擦除当前正在执行的指令。
- 对目标 Android 动态代码限制、性能及缓存维护进行可行性验证；不支持目标明确拒绝所请求能力，不能静默退回公开 handler 后仍报告 handler 加密。
- chaff 不得改变业务内存、副作用、异常或浮点语义；成本与轨迹分析效果分别测量。
- 完整性和 AntiDebug 是辅助层；盐来自会话不能证明自检不可摘除。

## 12. 产物、兼容性与集成

新云模式需要新的编译报告字段，至少证明区域身份、授权模式、实际材料依赖、原生回退移除、协议/VM 格式版本和后链接状态。敏感区域 strict 模式不能在预算失败后静默退回完整原生实现。

公开发布只包含公开清单与最终验证 ELF；秘密登记包独立处理。现有 link → targets → audit → seal → verify 流程中的封装与摘要顺序必须明确，最终身份不能因 seal 循环变化。

旧 cloudDispatch 模式与新模式明确区分。新模式请求不能被旧 runtime 满足；缺服务端构建记录、缺 runtime 或不支持 ABI 时给出明确失败。未启用新模式的普通混淆仍按现有行为运行。

首个端到端实现以 Android/AArch64 为基线。ARM32 继续保留现有非新云模式验收；新架构和 native JIT 支持只能在对应目标测试通过后分别声明。

## 13. 验收与可观察完成标准

### 13.1 正确性与生命周期

- 原生与保护结果差分覆盖已支持的整数、指针、浮点和调用 ABI；不通过放宽语义掩盖不支持项。
- A 每次启动建立新会话；B 在 110 秒预取、120 秒阻止新调用取得旧代；模式 3 各区域互不降级。
- 119 秒取得句柄的调用跨过 120 秒允许完成；过期后的新调用无材料必须在副作用前同步故障。
- 等待输入或仅执行原生代码时不因 B 到期后台退出；恢复网络后取得新材料可开始新的调用。
- 并发续期、迟到响应、递归、nested helper、退出和休眠恢复不混代，不延长旧期限。

### 13.2 协议与产物

- 错误签名、AEAD tag、构建、区域、会话、代号、输入及混搭载荷全部拒绝。
